# Логика оформления сообщений, анимаций и живого предпросмотра

Документ описывает фактическое поведение `dev_ui`: какие параметры общие, какие могут переопределяться стилем пользователя или ротации, как работает синхронизация рамок и как настройки попадают в Desktop Overlay и OBS Widget.

Документ разделён на две части: сначала пользовательское объяснение без привязки к реализации, затем технические зависимости в коде. Если поведение изменится в коде, этот документ следует сверить и обновить.

# Часть I. Как это работает

## 1. Два уровня оформления

У сообщения есть базовое оформление текущего представления (Overlay или Widget). Для обычных сообщений оно может быть дополнено индивидуальным стилем:

- **Глобальный стиль** — оформление по умолчанию для сообщений, которым не назначен отдельный стиль.
- **Индивидуальный стиль** — стиль, выбранный по нику пользователя или из очереди ротации. Он заменяет только те параметры, которые разрешено переопределять индивидуально. Остальные берутся из глобального оформления.

Глобальные настройки Overlay и Widget хранятся и редактируются отдельно. Поэтому у двух представлений могут быть разные базовые стили, пользовательские назначения и наборы ротации. При этом движок отображения и CSS у них общие.

## 2. Приоритет выбора стиля

Для обычного сообщения порядок выбора следующий:

```text
Новое обычное сообщение
        |
        v
Это награда за баллы?
   | да                 | нет
   v                    v
Системный стиль    Это подсвеченное упоминание
                        в Overlay?
                    | да          | нет
                    v             v
              Глобальный стиль   Есть стиль для ника?
                                  | да       | нет
                                  v          v
                            Стиль по нику  Ротация включена
                                            и содержит 2+ стиля?
                                           | да       | нет
                                           v          v
                                      Стиль ротации  Глобальный
```

Правила:

1. Награды не получают пользовательский стиль или стиль ротации.
2. Подсвеченные упоминания/ответы в Overlay используют стандартное оформление и не получают стиль по нику или ротации.
3. Если для автора задан индивидуальный стиль, он приоритетнее ротации.
4. Сообщение со стилем по нику не продвигает очередь ротации.
5. Если стиль по нику не найден, а ротация включена и содержит не менее двух вариантов, выбирается стиль ротации.
6. В последовательном режиме стили идут по очереди. В случайном режиме при пуле от трёх элементов подряд не выбирается один и тот же индекс.
7. Если ни одно из условий не сработало, используется глобальный стиль.

**Важно:** в OBS Widget подсветка упоминаний отключена. Поэтому сообщение, которое в Overlay могло бы стать подсвеченным упоминанием и обойти индивидуальные назначения, в Widget обрабатывается как обычное и может получить стиль по нику или ротации.

## 3. Какие параметры глобальные, а какие индивидуальные

Индивидуальный стиль не является полной копией независимого поведения чата. Он переопределяет ограниченный набор свойств. Все поля, не входящие в список индивидуальных, продолжают браться из глобальной конфигурации.

| Параметр | Глобальный | Может быть индивидуальным | Примечание |
|---|:---:|:---:|---|
| Размер шрифта | Да | Нет | Общий для обычных сообщений, индивидуальных стилей, событий и наград |
| Выравнивание текста | Да | Нет | Общее для всех типов сообщений |
| Семейство шрифта | Да | Да | Индивидуальный стиль может переопределить; события и награды используют системный шрифт |
| Анимация появления сообщения | Да | Да | Не путать с анимацией рамки |
| Направление чата | Да | Нет | Общее для всего списка |
| Режим расположения ника/сообщения | Да | Нет | Влияет на структуру обычного сообщения; системные события не получают блок автора и разделитель ника |
| Расстояние между плашками | Да | Нет | Настройка контейнера |
| Плавный сдвиг сообщений | Да | Нет | Настройка поведения ленты |
| Режим сплошной ленты | Да | Нет | Настройка поведения контейнера |
| Длительность показа сообщения | Да | Нет | Общее поведение удаления/затухания |
| Эффект рамки | Да | Да | Индивидуальный стиль задаёт собственный эффект |
| Скорость эффекта рамки | Да | Да | Индивидуальная скорость хранится в стиле |
| Синхронизация эффекта рамки | Да | Да | Индивидуальная настройка хранится в стиле |
| Толщина и цвета рамки | Да | Да | Индивидуальные значения заменяют глобальные |
| Форма плашки | Да | Да | Индивидуальный стиль может переопределить |
| Фон, режим, цвета и прозрачность | Да | Да | Индивидуальные значения заменяют глобальные |
| Цвет текста и обводка текста | Да | Да | Индивидуальные значения заменяют глобальные |
| Цвет и обводка ника | Да | Да | Индивидуальные значения заменяют глобальные |
| Изображение/узор на плашке и его параметры | Да | Да | Применяется только к текстовым сообщениям, не к событиям и наградам |
| Подсветка упоминаний | Да (только Overlay) | Нет | В Widget принудительно выключена |
| Фильтрация команд и игнорируемых ботов | Общие фильтры | Нет | Не являются оформлением отдельного сообщения |

Смысл таблицы: «глобальный» означает, что параметр задаётся в базовой конфигурации представления. Если для него разрешено индивидуальное переопределение, итоговое значение обычного сообщения может прийти из стиля по нику или из ротации.

### Что именно переопределяет индивидуальный стиль

Индивидуальный стиль может переопределить:

- фон: прозрачность, режим, цвета, направление и монохромный режим;
- форму плашки;
- толщину, цвет и второй цвет рамки;
- эффект рамки, скорость и синхронизацию;
- цвет текста и его обводку;
- настройки цвета и обводки ника;
- изображение/узор на плашке и его параметры;
- семейство шрифта;
- анимацию появления сообщения.

Индивидуальный стиль **не переопределяет** размер шрифта, выравнивание, направление чата, расположение ника/текста, расстояние между плашками, плавный сдвиг и режим ленты.

## 4. Типы сообщений и какие настройки на них действуют

| Тип сообщения | Стиль плашки | Размер шрифта | Выравнивание | Индивидуальный стиль / ротация |
|---|---|---|---|---|
| Обычное сообщение | Глобальный или индивидуальный | Глобальный | Глобальное | Да, по правилам приоритета |
| Упоминание/ответ в Overlay с включённой подсветкой | Специальная подсветка на базе глобального оформления | Глобальный | Глобальное | Нет |
| Упоминание/ответ в Widget | Глобальный или индивидуальный | Глобальный | Глобальное | Да, подсветка упоминаний отключена |
| Награда за баллы канала | Фиксированный системный стиль | Глобальный | Глобальное | Нет |
| Системное событие (подписка, подарок, рейд и т. п.) | Фиксированный системный стиль | Глобальный, отображается в размере 92% от него | Глобальное | Нет |

### Системные события

События используют отдельное компактное оформление: фиксированные фон, цвет, шрифт, полоса и геометрия. Настройки обычной плашки, пользовательские стили и ротация на них не распространяются.

### Награды за баллы канала

Награды используют отдельный фиксированный стиль с тёплым фоном и золотым акцентом. Они не получают пользовательский стиль, ротацию или голубую подсветку упоминаний. Семейство шрифта и оформление закреплены; общий размер шрифта и глобальное выравнивание сохраняются.

## 5. Анимация появления и анимация рамки — разные вещи

У сообщения есть два независимых вида анимации:

- **Анимация появления** — как новая плашка появляется в ленте (например, выезжает или проявляется). Она может быть глобальной или заданной индивидуальным стилем.
- **Анимация эффекта рамки** — как меняется/вращается/пульсирует рамка уже отображаемой плашки. Для неё действуют отдельные настройки эффекта, скорости и синхронизации.

Настройка скорости эффекта рамки не ускоряет и не замедляет анимацию появления сообщения.

## 6. Скорость эффекта рамки

Ползунок скорости имеет диапазон от 1 до 10:

| Значение | Результат |
|---:|---|
| 1 | Самая медленная скорость |
| 5 | Нормальная скорость (множитель длительности 1×) |
| 10 | Самая быстрая скорость |

Внутри используется множитель длительности:

`длительность = базовая длительность эффекта × (5 / скорость)`

Следовательно:

- чем выше значение ползунка, тем короче цикл и тем быстрее анимация;
- чем ниже значение, тем длиннее цикл и тем медленнее анимация;
- одинаковые эффекты с одинаковой скоростью имеют одинаковую длительность цикла.

У разных эффектов изначально разная базовая длительность. Поэтому одинаковая скорость на ползунке не делает разные эффекты одинаковыми по темпу.

## 7. Синхронизация анимации рамки

Синхронизация задаёт общую временную фазу анимации для сообщений, у которых включена эта опция.

### Когда синхронизация включена

- Каждое новое сообщение рассчитывает задержку от общих часов своего окна/страницы.
- Сообщения с одинаковым CSS-эффектом и одинаковой скоростью попадают в одну фазу цикла.
- Это относится и к обычным сообщениям, и к сообщениям из ротации, и к индивидуальным стилям пользователей — если в соответствующем стиле включена синхронизация.
- Сообщения с разными эффектами или разной скоростью используют разные циклы. Общая временная точка не означает, что визуальные фазы разных циклов обязаны совпадать.

Пример:

| Сообщение | Эффект | Скорость | Синхронизация | Ожидаемое поведение |
|---|---|---:|:---:|---|
| A | Pulse | 5 | Да | Общая фаза с B |
| B | Pulse | 5 | Да | Общая фаза с A |
| C | RGB | 5 | Да | Общий временной отсчёт, но другой цикл |
| D | Pulse | 8 | Да | Другой темп и фаза цикла |
| E | Pulse | 5 | Нет | Запускается независимо |

Таким образом, корректное сравнение синхронизации — одинаковые эффект **и** скорость при включённой опции.

### Когда синхронизация выключена

Каждая новая плашка начинает свой цикл независимо, с момента собственного создания. Визуально одинаковые сообщения могут находиться на разных стадиях анимации.

### Ротация и пользовательские стили

У каждого варианта стиля в ротации и у каждого индивидуального стиля есть собственные значения эффекта, скорости и синхронизации.

Поэтому:
- повторяющиеся варианты с одинаковым эффектом, скоростью и включённой синхронизацией должны совпадать по фазе;
- стиль с выключенной синхронизацией не обязан совпадать с другими;
- пользовательский стиль не обязан подчиняться глобальным значениям этих трёх параметров — его собственные значения являются частью индивидуальности оформления.

### Границы синхронизации

Синхронизация выполняется внутри одного отображения:
- Overlay синхронизирует сообщения внутри своего renderer;
- Widget синхронизирует сообщения внутри страницы OBS.

Overlay и Widget имеют разные экземпляры страницы и собственные часы браузерного контекста. Поэтому не следует ожидать побитового совпадения фазы между двумя разными представлениями.

## 8. Живой предпросмотр и сохранение

Изменения внешнего вида можно увидеть до сохранения. Это отдельный временный поток конфигурации, а не запись каждого изменения в постоянные настройки.

### Живой предпросмотр

1. Пользователь меняет настройку.
2. Окно настроек собирает актуальное оформление соответствующего представления, включая пользовательские стили и ротацию.
3. Отправка предпросмотра выполняется с небольшой задержкой (35 мс), чтобы не отправлять событие на каждый быстрый промежуточный ввод.
4. Overlay получает временную конфигурацию через IPC и вызывает общий движок отображения.
5. Widget получает временное состояние через локальный SSE-сервер; открытая страница применяет его тем же движком.
6. Предпросмотр не записывает временные значения в постоянное хранилище.

Вкладки Overlay и Widget имеют отдельные состояния оформления. Изменение предпросмотра одной вкладки не должно подменять конфигурацию другой.

### Сохранение

При сохранении настройки проходят нормализацию в главном процессе, записываются в конфигурацию, после чего актуальное состояние отправляется Overlay и Widget. Если изменены только параметры оформления, Twitch-подключение не должно перезапускаться без необходимости.

### Что обновляется у уже отображаемых сообщений

Движок обновляет существующие DOM-элементы не одинаково — это зависит от типа сообщения и наличия индивидуального стиля.

| Сообщения | Поведение при применении новой конфигурации |
|---|---|
| Обычные сообщения без индивидуального стиля | Получают обновления общих параметров оформления; классы эффекта/формы и синхронизация обновляются по соответствующим условиям |
| Сообщения с индивидуальным стилем | Сохраняют индивидуальное оформление; общий размер шрифта и выравнивание обновляются, остальные индивидуальные свойства не перезаписываются |
| Системные события и награды | Обновляются общий размер шрифта и выравнивание; фиксированное системное оформление сохраняется |

Для индивидуальных стилей изменение настроек применяется к новым сообщениям после получения новой конфигурации. Уже отображаемые сообщения сохраняют свой ранее рассчитанный индивидуальный набор CSS-переменных. Это сознательное следствие защиты индивидуального оформления от глобального перезаписывания.

Для обычных сообщений без индивидуального стиля живое обновление может менять уже запущенные эффекты и их фазу. Поэтому новые сообщения не обязаны визуально совпадать с существующими, если переключение синхронизации произошло между их созданием. Это не ошибка само по себе: после переключения существующие сообщения приводятся к новой общей фазе, а последующие сообщения используют общий временной отсчёт.

## 10. Ключевые функции и данные в `chat-view.js`

### Расчёт скорости

- `speedToDurationMultiplier(speedVal)` ограничивает значение диапазоном 1–10 и возвращает `5 / speed`, округлённое до двух знаков.
- `applyStyleVars(node, c)` записывает `--effect-speed-mult` из переданной конфигурации на корень представления или конкретное сообщение.
- В `chat.css` базовые длительности Pulse, RGB, Breathing и Cyber умножаются на `--effect-speed-mult`.

Базовые длительности CSS:
- Pulse — 2.2 секунды;
- RGB — 3 секунды;
- Breathing — 2.8 секунды;
- Cyber — 3.2 секунды.

Эффект Neon статический и не использует цикл анимации рамки.

### Расчёт синхронизации

- `computeSyncDelaySeconds()` получает `performance.now()` и возвращает отрицательное время в секундах.
- `applySyncDelayToElement(el, syncEnabled, sharedSyncDelay)` задаёт `--effect-sync-delay`: общую отрицательную задержку при включённой синхронизации или `0s` при выключенной.
- `addMessage(msg)` выбирает итоговый стиль `st = own || config`, задаёт классы эффекта, записывает `data-created-sec` и применяет задержку по `st.borderEffectSync`.

Общие часы здесь — часы текущего renderer. Overlay и Widget не разделяют один объект `performance`.

### Индивидуальные стили

- `OWN_STYLE_KEYS` — точный перечень свойств, которые индивидуальный стиль может переопределить.
- `mergeOwnStyle(style)` сначала копирует глобальный `config`, затем заменяет только поля из `OWN_STYLE_KEYS`, присутствующие в индивидуальном стиле.
- `pickOwnStyle(msg, highlight)` реализует приоритет: награда/подсвеченное упоминание → без индивидуального стиля; иначе стиль по нику → ротация → глобальный.
- `rotationLast` хранит индекс предыдущего элемента пула.

Изменяя глобальность нового параметра, необходимо проверять обе стороны контракта: его наличие в `OWN_STYLE_KEYS` и применение при создании/обновлении существующих сообщений.

### Обновление существующих сообщений

В `applyConfig(cfg)`:
1. Сохраняется предыдущая конфигурация и вычисляется, изменились ли глобальные параметры эффекта/скорости/синхронизации.
2. Устанавливается новая конфигурация и обновляются переменные корневого элемента и классы контейнера.
3. Для каждого существующего сообщения сначала обновляется глобальное выравнивание.
4. Для `.is-notice` и `.is-reward` обновляется только общий размер шрифта, после чего обработка завершается.
5. Для элементов с `_ownCfg` обновляется только общий размер шрифта, после чего обработка завершается.
6. Остальные сообщения получают общие классы оформления и, когда требуется, новую задержку синхронизации.

Это раннее завершение для `_ownCfg` — ключевой механизм, который не позволяет глобальному preview перекрашивать уже отображаемые индивидуальные стили.

## 11. CSS-контракт

Основные переменные:
- `--effect-speed-mult` — множитель длительности цикла;
- `--effect-sync-delay` — задержка/фаза CSS-анимации;
- `--plate-border-color`, `--plate-border-color-2` — цвета рамки;
- `--plate-border-width`, `--plate-radius` — геометрия рамки и плашки;
- `--font-size`, `--font-family`, `--text-align` — типографика.

Анимированные классы:
- `.effect-pulse` → `borderPulse`;
- `.effect-rgb` → `borderRgb`;
- `.effect-breathing` → `borderBreathing`;
- `.effect-cyber::after` → `cyberSpin`.

Класс `.effect-neon` задаёт статическое свечение. Значение `static` не включает анимированный класс.

Системные классы:
- `.is-notice` задаёт фиксированный стиль событий и уменьшает отображаемый размер шрифта до 92% от `--font-size`;
- `.is-reward` закрепляет системный шрифт, фон, геометрию и золотой акцент;
- `.is-mention` отвечает за голубую подсветку Overlay. Widget принудительно получает `highlightMentions: false`.

## 12. Поток preview и сохранения

### Preview

- `settings/settings.js::schedulePreview()` собирает `readAppearance('o_')`, `presets.readExtras('o_')` и общие фильтры, затем вызывает `previewOverlay()`.
- `scheduleWidgetPreview()` аналогично собирает состояние с префиксом `w_` и вызывает `previewWidget()`.
- Оба preview используют debounce 35 мс.
- `main.js` обрабатывает `preview-overlay` через `configLib.sanitizePreview()` и отправляет `config-applied` Overlay.
- `preview-widget` проходит через `sanitizePreview()`, затем рассылается как состояние Widget через SSE.
- Временный preview не сохраняется в electron-store.

### Save

- `settings/settings.js::save()` собирает общую конфигурацию, оформление Overlay и вложенную конфигурацию Widget.
- `main.js` в обработчике `save-config` нормализует данные через `configLib.normalizeConfig()`, сохраняет их и отправляет итоговые представления.
- `config.js::overlayView()` и `widgetView()` формируют отдельные конфигурации движка для соответствующих renderer.
- Overlay применяет конфигурацию через `onConfigApplied` → `view.applyConfig()`.
- Widget получает state через SSE и вызывает `view.applyConfig()`.

## 13. Что проверять при изменении механизма

Если меняется список глобальных/индивидуальных параметров:
- обновить или проверить `OWN_STYLE_KEYS`;
- проверить `mergeOwnStyle()` и `pickOwnStyle()`;
- проверить создание нового сообщения в `addMessage()`;
- проверить ветви `applyConfig()` для обычных сообщений, `_ownCfg`, `is-notice`, `is-reward`;
- проверить, что настройки Overlay и Widget нормализуются и передаются независимо.

Если меняется синхронизация или скорость:
- проверить все анимированные CSS-классы и их базовые длительности;
- проверить создание сообщения с глобальным и индивидуальным стилем;
- проверить включение/выключение синхронизации на уже отображаемых сообщениях;
- проверить изменение скорости без переключения эффекта;
- проверить последовательную и случайную ротацию;
- проверить повторяющиеся пользовательские стили;
- отдельно проверить Overlay и OBS Widget, поскольку это разные renderer с общим движком.

Если меняется preview/save:
- проверить debounce и сборку payload для обоих представлений;
- проверить `sanitizePreview()`, `overlayView()`, `widgetView()`;
- проверить возврат к сохранённому состоянию при отмене/закрытии окна настроек;
- убедиться, что preview не записывает временные значения в постоянную конфигурацию.
